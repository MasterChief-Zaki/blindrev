# C1 decisions — geodesy, camera maths, orbit, geodesy-verify

## Geodesy (`packages/core-sim/src/geodesy`)

- WGS84 from a = 6378137, 1/f = 298.257223563; all other constants derived in double precision.
- `ecefToGeodetic`: Vermeille (2004) closed form with GeographicLib's evolute/cancellation handling + up to 3 guarded
  Newton polish steps (accepted only if the residual drops). Defined everywhere: on the polar axis λ = 0; at the centre
  φ = +90°, h = −b; on the equatorial plane inside the evolute the foot point is taken on the side of z (north for ±0).
  λ ∈ (−π, π]. Optional `out` param added (API-compatible).
- `scaleToAltitude(p, h)` = p + (h − h(p))·n(φ, λ) (moves along the height coordinate line; exact).
- `wrapLonDeg` → (−180, 180] (−180 maps to +180, −0 → 0, non-finite → NaN); `clampLatDeg(lat, limit = 90)`.
- Extra exports: `wrapLonRad`, `wrap360Deg`, `geodeticDegToEcef`, `geodeticSurfaceNormal`, `primeVerticalRadius`,
  `meridionalRadius`, `meridianArc`/`inverseMeridianArc` (Helmert series to n⁴ + Newton inverse), `isometricLatitude`,
  `rhumbDirect`/`rhumbInverse`, `vec3*` helpers (all with optional `out`). Generic names (`clamp`) are not exported from
  the barrel to avoid `export *` collisions with C2's util.

## Camera (`packages/core-sim/src/camera`)

- State orbits a target on the ellipsoid (target height 0 unless `targetHeightM` is passed); heading clockwise from north
  [0, 360); pitch above the horizontal, −90 = straight down; camera = target − range·dir — same convention as Cesium's
  `HeadingPitchRange`, so the pose can be applied with `camera.setView({ destination, orientation: { direction, up } })`.
- **Pan stepping = WGS84 rhumb line (loxodrome), not a per-frame geodesic.** Reasons: (a) path-consistent — n steps of
  s/n land on the same point as one step of s (tested to < 1 µm), so motion is frame-rate independent ("no drift");
  constant-azimuth geodesic steps drift poleward/equatorward by ~s²·tanφ/2R per frame; (b) heading/map orientation is
  preserved while strafing (geodesic + heading transport would rotate a north-up view); (c) east/west panning keeps
  latitude bit-exact. Speed is true ellipsoidal arc length per second.
- Pan input magnitude capped at 1 (diagonals not faster). v(h) uses the exact camera ellipsoidal height of the current
  state (target at h = 0).
- Latitude wall at ±cfg.latClampDeg: poleward component stops at the wall, the east–west remainder slides along it.
- Tuning not in the `CameraConfig` contract (exported `DEFAULT_CAMERA_TUNING`, overridable per call): rotate 90°/s,
  tilt 45°/s, pitch ∈ [−90°, −10°], dt clamped to [0, 0.25 s] (NaN/negative dt → no-op; stalls don't teleport).
- Input signs: zoom > 0 = in; rotate > 0 = heading increases; tilt > 0 = pitch up (toward horizon);
  `wheelZoom` notches > 0 = in (renderer maps DOM `deltaY < 0` → +notches). Non-finite inputs → 0; invalid state fields
  fall back to `cfg.home`.
- `clampCameraHeight`: at least `cfg.terrainSamples` samples are considered — missing entries, `undefined` and
  non-finite samples all count as `lastKnownTerrainM`; result `heightM = max(desired, max(maxTerrain + minClearance,
  minEllipsoidalHeight))`; `lastKnownTerrainM` updates to the max of this frame's _defined_ samples (unchanged if none),
  so the camera can descend again once tiles load; non-finite lastKnown treated as 0. Also returns `floorM`, `clamped`.
- Helpers for renderer-globe: `cameraPoseFromState` (ECEF position/direction/up/right + geodetic of camera and target;
  `minCameraHeightM` lifts the camera along its own normal and re-aims), `cameraSegmentSamples` (camera→target points
  for `globe.getHeight`, camera nadir first), `solveCameraFrame` (pose → samples → clamp → lifted pose; pure given the
  sampler).

## Orbit (`packages/core-sim/src/orbit`)

- GMST = IAU-82 (Vallado/Spacetrack #3 revisited), UT1 ≈ UTC by default; optional `ut1MinusUtcS` on `gmstRad` and
  `propagateTle` (Bulletin A DUT1) because the budget shows the UT1 term (≤ 468 m) matters for the < 1 km gate.
  Computed with integer-ms day reduction (≈1e-15 rad precision).
- TEME→ECEF: R3(θ_GMST) only (no polar motion); v_ecef = R3·v_teme − ω×r with ω = 7.292115146706979e-5 rad/s (Vallado).
- `propagateTle` caches up to 16 satrecs; returns null on invalid TLE/date/SGP4 error. `tleEpoch` parses line-1 cols
  19–32 (YY < 57 → 20YY), rounded to the nearest ms; unparseable → Invalid Date (always stale).
- `ephemerisStatus`: stale iff |now − epoch| > maxAgeHours (exactly 72 h is FRESH; future epochs use |age|);
  `ageHours` is signed.
- `nadirGroundTrack` emits ⌊duration/step⌋ + 1 points (capped at 20 000), skipping failed epochs. Extra exports:
  `splitTrackAtAntimeridian`, `tleFromSnapshot`, `tleInclinationDeg`, `tleMeanMotionRevPerDay`, `tlePeriodMinutes`,
  `ecefToTeme`, `temeVelocityToEcef`, `J2000_UNIX_MS`.

## geodesy-verify

- Two Vitest projects: `correctness` (independent oracles: reduced-latitude forward, Eberly bisection inverse,
  implicit-surface normal, exact analytic vectors, EPSG GN7-2 published example, round-trip closure) and `parity`
  (CesiumJS). Cesium is imported only in `src/parity.ts`; the correctness project never loads it.
- `test` script = correctness (gating) then parity, printing `PARITY FAIL - non-blocking …` instead of failing
  (spec §8). `test:correctness`/`test:parity` run them strictly. `verify` prints the table; exit 1 only on correctness
  failure (`--strict-parity` → exit 2 on parity failure); `--json <file>` saves results.
- Parity diagnostics measure both Cesium and core-sim against the oracle on the same points to attribute gaps.

## Spikes

- Spike D (geodesy): correctness PASS (worst 2.2e-7 m vs 1e-6 m). Parity FAIL non-blocking: Cesium-side precision
  (`scaleToGeodeticSurface` EPSILON12 stop → 3.1e-6 m; `asin` latitude near poles → 4 mm at GEO lever arm).
- Spike C: gate NOT VERIFIED — Horizons' NISAR (−165053) trajectory is TLE-derived. Standing kill: nadir track only.
  Deviation from spec §11 example: polar motion is 10–17 m at NISAR's radius, not "≤ ~1 m".
