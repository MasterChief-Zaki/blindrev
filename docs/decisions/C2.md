# C2 decisions: game logic (temporal FSM, ROI, scoring, util)

Owned paths: `packages/core-sim/src/{temporal,roi,scoring,util}/**`. All shared types come from `../contracts`. There are no imports from C1's `geodesy/camera/orbit`: ROI longitude wrap and latitude clamp are private copies.

## util

- `digestHex` is a pure-TS **SHA-256** (lower-case hex). I chose it over FNV-1a because it is collision-resistant and lets `decodeMask` check `MaskAsset.sha256`. It is checked against the FIPS 180-4 vectors. Strings go through a local UTF-8 encoder, because core-sim has no DOM lib and so no `TextEncoder`.
- `daysBetween(a, b)` is **signed** (`b − a`, fractional days) and returns `NaN` on unparseable input. I wrote my own strict ISO-8601 parser (`parseIsoUtcMs`, days-from-civil integer maths) because `Date.parse` reads zone-less date-times as host-local time. Zone-less input is treated as **UTC**.
- `mulberry32` is the standard algorithm. The test pins 3 outputs for seed 12345 as a **regression pin**: they were recorded from this implementation, not taken from an external oracle.
- The package index exports only `mulberry32, digestHex, sha256Hex, daysBetween, parseIsoUtcMs`. Internal helpers stay unexported to avoid `export *` name clashes with C1 (`clamp`, `wrapLonDeg`, …).
- `util/testFixtures.ts` holds the test-only `makeStep` / `makeOpticalStep` (TEST_FIXTURE data). It is not exported from the index.

## temporal (FSM)

- The full transition table is in the doc comment of `temporal/watch.ts`. Interpretations:
  - **Rest state** `rest(i)` = IDLE if step i is available, else PAUSED_UNAVAILABLE. The initial state is `rest(initialIndex)`. At the end of playback the state is `rest(index)`, which is IDLE in every case except a mission with no available step ahead of an unavailable starting step. The literal spec says "back to IDLE"; this exception is the only deviation.
  - **TICK** (PLAYING only) scans forward with a bounded loop. It emits one `NoAcquisition` per skipped unavailable step and lands on the next available step. When none is left it emits `EndReached`, keeps the index, and goes to `rest(index)`. TICK never moves onto an unavailable step during playback.
  - **PLAY** when no available step lies after the current index **rewinds to step 0** (StepChanged, plus NoAcquisition if step 0 is unavailable). PLAY from PAUSED_UNAVAILABLE enters PLAYING on the unavailable step, and the next TICK moves on.
  - **STEP_FORWARD / STEP_BACK / SCRUB_TO** outside a scrub are seeks that **pause playback**. A seek landing on an available step gives IDLE; one landing on an unavailable step gives PAUSED_UNAVAILABLE plus NoAcquisition.
  - **Scrub flag:** SCRUB_START sets it and SCRUB_END clears it. While scrubbing, the state is SCRUBBING on available steps and PAUSED_UNAVAILABLE on unavailable ones (with NoAcquisition). SCRUB_START from PAUSED_UNAVAILABLE keeps that state. SCRUB_END never resumes playback.
  - PLAY, PAUSE and TICK during a scrub are ignored. RESET clears the scrub and seeks to `initialIndex`.
  - **NoAcquisition de-dup:** it is emitted only when the index changed or the state was not already PAUSED_UNAVAILABLE, so scrub jitter does not spam the live region.
  - **Clamping:** indices are rounded and clamped. `±Infinity` maps to the ends; `NaN` is a no-op. An empty step list throws a `RangeError`.
- Emission order within one dispatch is NoAcquisition/StepChanged in sweep order, then EndReached, then one StateChanged. All emissions of a dispatch share one `atMs`.
- **Clock:** the default is a _logical_ clock (the dispatch sequence number, 0, 1, 2…), so core-sim never reads wall time. The UI injects `performance.now`.
- The journal records **every** dispatch, including no-ops (`from === to`), as frozen copies. It is a ring buffer, `journalLimit` default **10,000**, so a 30-min soak cannot grow it without bound. This is an addition to the contract's options.
- Subscribers are notified only when a dispatch emitted something. The snapshot object is replaced only on change, so it is safe for `useSyncExternalStore`. If a subscriber throws, the others still run and the first error is rethrown.
- There is no initial emission at construction, because `createTemporalWatch` cannot return one. The UI renders the initial PAUSED_UNAVAILABLE from `getSnapshot()`.

## ROI

- **Edge model:** ROI edges are straight lines in lon/lat (plate carrée), the same geometry as the EPSG:4326 raster that is scored. `sphericalAreaKm2` uses **great-circle** spherical excess on the authalic sphere R = 6,371,007.2 m, as the spec requires. It is used **only for the A_min/A_max bounds check**. The gap between the two edge models is about 1e-4 relative for 0.2° boxes and at most about 6e-4 for 2,500 km² boxes at 36° N, which is irrelevant for bounds checking. It is documented in code and in tests.
- The area formula is per-edge `2·atan2(tan(Δλ/2)(tan(φ1/2)+tan(φ2/2)), 1+tan(φ1/2)tan(φ2/2))`, with Δλ taken the short way. It is checked against an independent Girard oracle to 8e-13 … 4e-10 relative.
- **Lattice:** validated coordinates are snapped to **1e-9°** (≈ 0.1 mm). That makes the orientation predicates exact: a double fast path with an error bound, falling back to exact BigInt. Collinearity and touching are therefore decided exactly. Returned rings carry the snapped values. `nudgeVertex` snaps too, so there is no drift (0.001 × 3 = 0.003 exactly).
- **Error order:**
  - non-finite → `DEGENERATE`;
  - fewer than 3 distinct vertices after dropping consecutive and closing duplicates → `TOO_FEW_VERTICES` (180° and −180° count as the same point);
  - ring loops a pole (net longitude winding ≠ 0) → `DEGENERATE`;
  - longitude span ≥ 360° → `DEGENERATE`;
  - all collinear → `DEGENERATE`;
  - any self-intersection → `SELF_INTERSECTION`. This covers proper crossings, touching or shared non-adjacent vertices, collinear overlaps, and fold-back spikes between adjacent edges;
  - otherwise area < min → `AREA_TOO_SMALL`, or area > max → `AREA_TOO_LARGE`. Both bounds are inclusive.

  Only one geometry error is reported, because later checks are meaningless after an earlier failure.
- For geometry failures `areaKm2 = 0` and `rings = []`. For area failures the real area and rings are returned, so the UI can still draw and size them.
- Edges always take the **short way round** (|Δλ| ≤ 180°). An edge of exactly 180° is resolved as +180°, which is deterministic but arbitrary.
- **Antimeridian:** the ring is unwrapped, shifted so its min lon is in [−180, 180), and if it extends past 180° it is clipped with Sutherland–Hodgman into a west ring (≤ 180) and an east ring (shifted −360, ≥ −180). Cut points use canonical endpoint order, so both halves share exactly the same vertex. Concave rings may keep zero-width bridges along the cut line; these have no effect under even-odd.
- The pole clamp is |lat| ≤ 89.9°, applied before everything else. Clamping can create duplicates, which are then dropped.
- Messages follow the brand voice: short, plain, warm (for example "The outline crosses itself. Move a point so the edges don't cross."). They are exported as `ROI_MESSAGES`.
- `nudgeVertex(vertices, index, dir, coarse, stepDeg = 0.001, coarseFactor = 10)`. The 6th parameter is an addition; pass `GameConstants.roiNudgeCoarseFactor`. An out-of-range index returns an unchanged copy instead of throwing.
- `pointInRings` uses the half-open straddle rule (`a.lat > lat !== b.lat > lat`) and counts crossings strictly east of the point (left and bottom boundaries inside, right and top outside). It also tests the point at lon ± 360 and combines parities, so unwrapped rings work. It agrees bit-for-bit with `rasterizeRings` at pixel centres; this is tested.

## Scoring

- **Gate order:** STEP_UNAVAILABLE → DT_TOO_SHORT → CRS_MISMATCH → GRID_MISMATCH → ROI_INVALID → coverage (LOW_COHERENCE / CLOUD_COVER) → TOO_FEW_VALID_PIXELS → SCORE.
- **Δt** = |`daysBetween(stepA.date, stepB.date)`|, so A/B order is irrelevant. The same step twice gives Δt 0 → DT_TOO_SHORT. An unparseable date also gives DT_TOO_SHORT, with a "couldn't read the dates" message; there is no dedicated code for it.
- **CRS:** every passed grid (reference + QA) must be `EPSG:4326`. `step.crs` is the _display_ raster's CRS and is **not** checked. `reprojectMercatorMaskTo4326` (nearest neighbour at target pixel centres, source bounds in degrees, 0 outside the source) is for the data pipeline. It uses `log/tan`, so it is not on the bit-deterministic path.
- **Grids** must match the reference exactly: width, height, all four bounds, and `data.length === w*h`. There is no ±1 px tolerance in scoring. `maskRegistrationMaxPx` is D's pipeline gate and `scoreRoi` does not use it.
- **ROI:** rings are rasterised onto the reference grid. Empty rings, rings with fewer than 3 vertices, or non-finite points → ROI_INVALID, and so does a zone covering 0 pixels. `scoreRoi` does **not** re-run self-intersection or area checks; `validateRoi` owns those, which avoids two gates with slightly different floating-point areas.
- **Validity:** a pixel is valid iff it is non-zero in **every** QA grid. An empty `qa` array means every pixel is valid.
- **Invalid reference pixels are excluded from fn** (and from tp/fp). Change hidden by low coherence or cloud cannot count against the player. fn is counted over the whole grid, not only inside the ROI.
- If tp+fp+fn = 0 then IoU = 0, and the same for zero precision or recall denominators. This cannot happen once the QA gates pass with `qaMinValidPixels ≥ 1`.
- Tiers: PASS if iou ≥ iouPass, PARTIAL if iou ≥ iouPartial, else FAIL (inclusive). An advisory is added when precision **or** recall < `advisoryPrecisionRecall`. Each advisory string quotes **both** numbers (`toFixed(1)`, deterministic).
- **SAR vs optical:** a step counts as SAR if `displacement !== null` or its instrument matches `/sar|radar|interferom/i`. `CLOUD_COVER` is used only when **both** steps are optical; mixed pairs get the coherence wording. The LOW_COHERENCE message is the exact spec string. For optical steps TOO_FEW_VALID_PIXELS says "cloud-free" instead of "high-coherence".
- **Digest:** SHA-256 over a canonical text containing:
  - the version tag `blindrev.score.v1`;
  - the grid spec;
  - the bit-packed **ROI raster**, which is what makes it independent of winding, start vertex and ring order;
  - the bit-packed reference mask;
  - the bit-packed **combined validity mask**, independent of QA order and duplicates;
  - the sorted step pair `date|stepId|processingVersion`;
  - all 9 `ScoringConfig` fields in a fixed order;
  - the result fields and the advisory strings.

  QA_DIAGNOSTIC and REJECTED outcomes carry no digest, which matches the contract.
- `decodeMask(asset, bytes, opts?)` also accepts a `Uint8Array` and an optional `{ verifySha256 }` (default true). It **throws `MaskDecodeError`** on a wrong CRS, a bad grid, a byte-length mismatch, or a SHA-256 mismatch. Verification is skipped when `asset.sha256` is not 64 hex chars, for example a placeholder. Values are normalised to 0/1 in a fresh array.
- Extra exports: `countSet`, `pixelCentreLons/Lats` (the exact contract formula, for D and U to reuse), `isSarStep`, `LOW_COHERENCE_MESSAGE`, `CLOUD_COVER_MESSAGE`, `SCORE_DIGEST_VERSION`, `MaskDecodeError`, and the types `ScoreTier`, `MercatorMaskGrid`, `DecodeMaskOptions`.
