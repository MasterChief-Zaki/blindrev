## 1. The CSP that ships

Exact string from `packages/app-shell/src-tauri/tauri.conf.json` → `app.security.csp`:

```
default-src 'self'; script-src 'self'; worker-src 'self' blob:; img-src 'self' data: blob: https://assets.ion.cesium.com https://gibs.earthdata.nasa.gov; connect-src 'self' ipc: http://ipc.localhost https://ion.cesium.com https://assets.ion.cesium.com https://gibs.earthdata.nasa.gov https://celestrak.org; style-src 'self' 'unsafe-inline'
```

Plus this sibling setting in the same `security` block:

```json
"dangerousDisableAssetCspModification": ["style-src"]
```

### GAP: `https://api.cesium.com` is missing from `connect-src`

Both the SPEC baseline and the shipped CSP list `https://ion.cesium.com`. CesiumJS does not use that host for data. The first request of `CesiumTerrainProvider.fromIonAssetId(1)` goes to `https://api.cesium.com/v1/assets/1/endpoint?access_token=<token>`:

- `@cesium/engine` 26.5.0 (bundled with cesium 1.147.0), `Source/Core/Ion.js` line 37: `Ion.defaultServer = new Resource({ url: "https://api.cesium.com/" });`
- `Source/Core/IonResource.js` `_createEndpointResource`: `url: v1/assets/${assetId}/endpoint`, `queryParameters = { access_token: accessToken }`.
- In the engine source, `ion.cesium.com` only appears inside Google credit HTML (`https://assets.ion.cesium.com/google-credit.png`).

Effect: in the packaged app, with a token configured, the endpoint fetch is blocked by CSP. `renderer-globe/src/globe.ts` `loadWorldTerrain()` catches the failure and falls back to the ellipsoid with the message "World Terrain unavailable (network) — ellipsoid terrain". So the app stays usable, but **World Terrain can never load in the packaged build**. In the browser dev build the CSP is not applied (no CSP `<meta>` in `index.html`), so World Terrain works there. A dev-mode test therefore does not prove the packaged behaviour.

Proposed fix (owner: agent S, file `tauri.conf.json`): add `https://api.cesium.com` to `connect-src`. `https://ion.cesium.com` can stay or go; nothing in CesiumJS 1.147 needs it. Then re-test in the packaged app with a token (row T1).

## 2. Network endpoints: measured headers

All requests below were made once from this machine with `curl` on 2026-11-15 between 20:05 and 20:07 UTC. Only one request was sent to CelesTrak.

### 2.1 CelesTrak GP API

Command:

```
curl -s -D - -o celestrak-body.txt -H "Origin: http://tauri.localhost" -A "blindrev-docs-check/0.1" \
  "https://celestrak.org/NORAD/elements/gp.php?CATNR=65053&FORMAT=TLE"
```

Response headers, verbatim:

```
HTTP/1.1 200 OK
Content-Type: text/plain; charset=UTF-8
Server: Microsoft-IIS/10.0
X-Powered-By: PHP/8.5.12
Content-Disposition: filename="65053.txt"
Access-Control-Allow-Origin: *
Date: Sun, 15 Nov 2026 20:06:03 GMT
Content-Length: 168
```

Body: the same three lines as `data/tle/nisar-65053.snapshot.json` (epoch `26319.51760558`, line-1 checksum 3, line-2 checksum 4).

Findings:

- `Access-Control-Allow-Origin: *`: a cross-origin `fetch` from `http://tauri.localhost` is allowed. The request is a simple GET with no custom headers, so there is no preflight.
- No `Cache-Control`, `ETag`, `Last-Modified` or `Expires`. The WebView2 HTTP cache has nothing to validate against. The app does not rely on it: `mission/nisar.ts` fetches with `cache: "no-store"` and keeps its own `localStorage` copy (`blindrev.tle.v1`).
- No rate-limit headers are returned. CelesTrak asks clients not to fetch the same data more than once every 2 hours. The app's control is `REFRESH_MIN_INTERVAL_MS = 2 * 3600 * 1000`, checked against the time of the last **successful** fetch.

## 4. How to run the "verify in packaged app" checks

Release builds of Tauri do not open devtools. Use a debug build of the shell with the production web bundle:

```
pnpm --filter @blindrev/app-shell tauri build --debug --no-bundle
packages\app-shell\src-tauri\target\debug\blindrev.exe
```

`tauri build` runs `beforeBuildCommand` (`pnpm exec vite build`), so the page is the production bundle and the CSP is applied. Right-click → Inspect opens the WebView2 devtools in a debug build. This command was **not** run by agent W (the Rust target directory was in use by other agents); the flags are standard Tauri CLI flags.

In the devtools console:

1. `location.origin` → expect `http://tauri.localhost` (T2).
2. Console: no `Refused to …` CSP messages during menu → hub → mission → validate (T5, T6, §1 style-src).
3. `__BLINDREV__.state().tle` → `source` is `celestrak` or `cache` online, `snapshot` offline; `refreshLog` explains why (T3).
4. Network panel: GIBS basemap tiles show `(disk cache)` on the second launch within 3 days (T4).
5. With a token in `.env.local` **and** `https://api.cesium.com` added to `connect-src`: `__BLINDREV__.state().globeStatus.terrain` → `WORLD_TERRAIN` (T1, T2a, T7). Without the CSP fix expect `ELLIPSOID` and the message "World Terrain unavailable (network) — ellipsoid terrain".
