### 4.4 Geodesy, camera maths and orbit

- WGS84 from a and 1/f only. `ecefToGeodetic` = Vermeille (2004) + GeographicLib evolute handling + up to 3 guarded Newton steps; defined everywhere (polar axis λ = 0; centre → φ = +90°, h = −b). `scaleToAltitude` moves along the height coordinate line (exact). `wrapLonDeg` → (−180, 180]. [C1]
- Camera state orbits a target on the ellipsoid; heading clockwise from north; pitch −90 = straight down (same convention as Cesium `HeadingPitchRange`). **Pan stepping uses rhumb lines**, not per-frame geodesics: frame-rate independent (n steps of s/n = one step of s to < 1 µm), keeps map orientation while strafing, keeps latitude exact on east–west pans. Latitude wall at ±89.5° slides along. Rotate 90°/s, tilt 45°/s, pitch ∈ [−90°, −10°], dt clamped to 0.25 s. [C1]
- `clampCameraHeight`: missing / undefined samples count as last-known terrain; floor = max(maxTerrain + minClearance, minEllipsoidalHeight); last-known follows defined samples so the camera can descend once tiles load. [C1] Renderer hardening after the first A2 run: per-cell (~55 m) height cache, and last-known = max(core-sim value, last frame's floor terrain). [G]
- Orbit: GMST IAU-82, UT1 ≈ UTC by default, optional `ut1MinusUtcS` (Bulletin A DUT1) because the UT1 term reaches ~468 m. TEME → ECEF by R3(θ) only (no polar motion); velocity includes −ω × r. `ephemerisStatus`: exactly 72 h is FRESH. [C1]
- Deviations from SPEC text: polar motion is 10–17 m at NISAR's radius, not "≤ ~1 m"; NISAR geodetic height is 752–779 km, not 747 km (the nominal figure is relative to a mean radius). [C1]
- `geodesy-verify`: separate `correctness` (gating) and `parity` Vitest projects; Cesium is imported only by the parity module. [C1]

### 4.5 Temporal watch, ROI, scoring

- `digestHex` is pure-TS SHA-256 (FIPS 180-4 vectors), chosen over FNV-1a so `decodeMask` can verify `MaskAsset.sha256`. `daysBetween` is signed, with a strict ISO parser that treats zone-less input as UTC. [C2]
- FSM: rest state = IDLE on an available step, PAUSED_UNAVAILABLE otherwise (only deviation from "back to IDLE" at end of playback). TICK skips unavailable steps with one NoAcquisition each; PLAY at the end rewinds to step 0; seeks pause playback; NoAcquisition is de-duplicated so scrub jitter does not spam the live region; logical clock by default; journal is a ring buffer of 10,000 entries. [C2]
- ROI edges are straight in lon/lat (the scored geometry); the area check uses great-circle spherical excess on R = 6,371,007.2 m, as the SPEC requires — the two differ by ≤ ~6e-4 relative, irrelevant for bounds. Coordinates snap to 1e-9° so predicates are exact (BigInt fallback). One geometry error is reported at a time, in a fixed order. Antimeridian rings are split with Sutherland–Hodgman. `nudgeVertex` gained a 6th parameter, `coarseFactor`. Messages follow the brand voice. [C2]
- Scoring gate order: STEP_UNAVAILABLE → DT_TOO_SHORT → CRS_MISMATCH → GRID_MISMATCH → ROI_INVALID → coverage → TOO_FEW_VALID_PIXELS → SCORE. Δt is absolute. Grids must match exactly (no ±1 px tolerance in scoring; registration is D's pipeline gate). A pixel is valid only if valid in every QA grid. **Invalid reference pixels are excluded from fn**, so change hidden by low coherence cannot count against the player. `CLOUD_COVER` only when both steps are optical. Digest covers version, grid, bit-packed ROI raster, reference, validity, sorted steps, all config fields and the result. [C2]

### 4.6 Mission data and data-forge

- **Step cadence: every third 12-day cycle (36 d), 9 steps**, s01 2025-12-31 (reference) … s09 2026-10-15.
